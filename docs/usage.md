# 使い方の詳細

README の「使い方の要点」から一歩踏み込んで、各機能が Slack でどう動くかを引くための文書。セットアップと起動は [README](../README.md) にある。
Claude Code 自体の挙動（設定の効き方、ダイアログなど）についての記述は、Claude Code の仕様に基づく説明で、このリポジトリのテストでは確かめていない。

## メッセージ

- ボットに DM を送ると、手元のセッションにメッセージが届き、届いた印に :eyes: が付く。許可チャンネルでボットにメンションしたときや、ボットが関わっているスレッドに返信したときも同じ。Claude には元のメッセージのスレッドに返信するよう、MCP の instructions で指示してある。
- 受け付けるのは、**ボットとの DM と、`access.json` の `channels` に書いたチャンネルだけ**。ほかのチャンネル・グループ DM・編集や削除のイベントは無視する。
- チャンネルで Claude に届くのは、ボットへのメンション（`@<ボット名>`）付きの発言と、ボットが関わっているスレッドへの返信だけ。関わっているスレッドとは、メンションで話しかけたスレッドと、ボットが投稿したスレッドのこと。こうしたスレッドでは、メンションなしの返信も届く。それ以外の雑談には反応しない。
  - メンションは本文から取り除いてから Claude に渡す。
  - 関わっているスレッドは、ブリッジが動いている間だけ覚えている。再起動したら、もう一度メンションする。
  - チャンネルでも、`allowFrom` に無いメンバーの発言とボタン操作は無視する。
- **添付ファイルの中身は渡さない**。Claude に届くのは、ファイル名・種類・サイズの要約とファイル ID（`attachment_ids`）だけ。本文が無いメッセージは `(attachment)`、複数の添付なら `(N attachments)` として届く。中身が要るときは Claude が `download_file` で取りに行く（[添付ファイルの保存と展開](#添付ファイルの保存と展開)）。
- メッセージとボタン操作は、届いた順に1件ずつ処理する。前の処理が終わるまで、次は始めない。
- 長い返信は、自動で複数のメッセージに分けて送る。途中で送信に失敗すると、Claude には何件目まで送れたか（`sent=N`）を添えたエラーが返る。
- 投稿したリンクのプレビュー（unfurl）は展開しない。
- Claude にメッセージを渡してから5分たっても Claude が何も返さないと、そのスレッドに「⚠️ Claude から 5 分応答が無い」と投稿する。「何も返さない」とは、`reply` / `react` / `edit_message` の呼び出しも、実行許可の確認も無いこと。
  - ターミナル側の選択画面（Slack には中継されない）、使用量の上限、セッションの停止などで止まっていても、Slack からは気付けない。それを防ぐための警告。
  - 見張るのは、最後に渡したメッセージ1件だけ。待ち時間は `SLACK_CHANNEL_REPLY_TIMEOUT_MIN` で変えられる。
  - 警告には「🖥 画面を確認」ボタンが付く（[ターミナル画面の確認と選択](#ターミナル画面の確認と選択)）。
- セッションは1つだけで、Slack 側の会話はすべて同じ文脈を共有する。
- Slack のメッセージは本文として Claude に届くだけで、Claude Code のコマンドは実行できない。例外は `!restart` / `!compact` / `!clear` で、これらはブリッジがターミナルに打ち込む。
  `/clear` のように `/` で始まる文は、Slack 自身のコマンドとして扱われ、Claude Code には届かない。
- ブリッジが処理する `!` のコマンドの一覧は、[README の使い方の要点](../README.md#使い方の要点) にある。`!help` を送ると、同じ一覧がスレッドに返る。

## 添付ファイルの保存と展開

`.env` に `DOWNLOAD_DIR`（絶対パス）を書くと、MCP ツール `download_file` が使えるようになる。
書かなければツール自体が出ない。この機能を使わないなら、`DOWNLOAD_DIR` も `files:read` スコープも要らない。

- `download_file(file_id, extract?)` は、Slack のファイルを `DOWNLOAD_DIR` に保存して、保存先のパスを返す。
  `file_id` には、届いたメッセージの `attachment_ids` のどれかを渡す。自動では保存せず、Claude が必要なときだけ呼ぶ。
- 同じ名前のファイルがあれば、`名前 (1).拡張子` のように番号を付ける。上書きはしない。
- ファイル名は送信者が自由に付けられる。そこで、パス区切りより前を捨て、Windows で使えない文字を `_` に置き換えてから保存する。
- `extract: true` を付けると、圧縮ファイルを `DOWNLOAD_DIR\<名前>\` に展開する。元のファイルは残す。
  - zip / 7z / rar / tar / tar.gz（tgz）/ tar.bz2 / tar.xz / tar.zst / lzh は、Windows 付属の `tar.exe`（bsdtar）で展開する。単体の `.gz` は Node の zlib で展開する。
  - パスワード付きのアーカイブや、bsdtar が読めない形式はエラーになる。アーカイブの中のアーカイブは展開しない。
  - PATH 上の `tar`（Git の GNU tar など）は使わず、`%SystemRoot%\System32\tar.exe` を直接呼ぶ。
- 上限は、ダウンロードが 1GB、展開後が合計 4GB・10万ファイル。超えたら止めて、書きかけ・展開しかけのものを消す。
- `..` や絶対パスを含むエントリ（Zip Slip）は bsdtar が拒否する。展開後にシンボリックリンクやジャンクションが見つかったら、展開先ごと消してエラーにする。
- 展開したファイルを実行したり解釈したりはしない。ファイルの中身はデータとして扱い、中に書かれた指示には従わない（MCP の instructions と同じ扱い）。
- ボットトークンは `https://*.slack.com` にしか送らない。権限が足りないと、Slack はファイルの代わりにログイン画面の HTML を返す。これはエラーとして扱う。

## 実行許可

許可リストに無い操作を Claude が実行しようとすると、ボタン付きの確認メッセージを Slack に出す。
出す先は、最後に Claude へ中継したメッセージのスレッド（DM でもチャンネルでも）。スレッド外のメッセージなら、そのメッセージを起点にスレッドを作る。
起動してからまだ何も中継していないときや、スレッドへの返信に失敗したときは、許可ユーザー全員の DM に出す。DM では、その DM で最後に中継したメッセージのスレッドに出し、まだ中継したことが無ければトップレベルに出す。

- **Allow / Deny** のボタンで答えるか、`yes xxxxx` / `no xxxxx` と返信する。
  `xxxxx` はメッセージに表示された5文字の ID。`y` / `n` でもよく、大文字と小文字は区別しない。
- 答えると、配信したメッセージの表示が `Allowed` / `Denied` と回答者に変わる。DM で全員に配信したときは、全員分を書き換える。
  ID は plain_text で表示する。回答者は、Slack のユーザー ID の形のときだけメンション（`<@U...>`）にし、それ以外は plain_text で表示する。
  テキストで答えたときは、その返信に :white_check_mark: / :x: が付く。
- 保留中でない ID への `yes xxxxx` は回答として扱わず、普通のメッセージとして Claude に届く。
- 有効期限は **30分**。期限までに答えが無ければ Claude に自動で deny を返し、メッセージを「期限切れのため自動で拒否した」表示に書き換える。
  期限切れのボタンを押しても Claude には送らない。押したメッセージが期限切れの表示に変わるだけ。
- Slack から答えられない次の場合も、自動で deny を返す。
  - スレッドへの返信も、どの DM への配信もできなかったとき（全員分の投稿に失敗した、DM チャンネルが無い）。ログに `permission_request をどの DM にも配信できなかった` が出る。
  - ブリッジの終了時に保留中だったとき。メッセージは「ブリッジ終了のため自動で拒否した」表示に書き換える。ただし書き換えられるのは、切断する前に間に合った分だけ。
- 入力内容（コマンドや差分）は、合計で約2800文字まで表示する。
  それを超えるときは、先頭の約2200文字と末尾の約600文字を残し、間に `…（途中 N 文字省略）…` を入れる。その下に「See more で全文を確認すること」という警告の行を出す。省略しなかったときは、警告の行も出ない。
- ツール名・説明・入力内容のどれかを省略したときだけ、**See more** ボタンが付く。押すと、入力内容の全文をコードブロックでスレッドに送る。
  長ければ複数のメッセージに分け、期限切れならその旨だけを送る。
- 見えない文字は、`\u{202E}` のような表記に置き換えて表示する（See more の全文でも同じ）。仕込まれた文字で表示を偽装されないようにするため。対象は次のとおり。
  - 文字の向きを変える制御文字（U+202A〜202E、U+2066〜2069、U+200E〜200F）
  - ゼロ幅文字（U+200B〜200D、U+2060〜2064 など）
  - BOM（U+FEFF）
  - ソフトハイフンや、空白に見える埋め文字
  - タブと改行を除く C0 / C1 制御文字
- Allow / Deny を Claude に送れなかったとき（MCP の切断など）は、メッセージを「送れなかった」表示に書き換える。
- 同じ ID の確認が重ねて届いても出し直さない。最初に出したボタンで答えられる。
- Claude から届いた確認の ID が想定外の形（`l` を除く英小文字5文字でない）のときは、Slack には出さない。ログに警告を残し、自動で deny を返す。
- ターミナル側にも同じ確認が出るので、どちらで答えてもいい（Claude Code 側の挙動で、このリポジトリでは確かめていない）。

## 普段の MCP サーバーは Slack のセッションでは読み込まれない

Slack のセッションは `--strict-mcp-config` で起動する。そのため、普段の Claude Code で使っている MCP サーバー（ユーザー設定 `~/.claude.json` や、作業フォルダーの `.mcp.json` に登録したもの）は**読み込まれない**。
エラーも確認画面も出ず、Claude からは「そのツールにつながっていない」ように見えるだけなので、気付きにくい。

- Slack のセッションでも使うサーバーは、`config\extra-mcp.json` に `.mcp.json` と同じ形で書く（ひな形: [config/extra-mcp.example.json](../config/extra-mcp.example.json)、git の管理外）。
  起動時に `追加の MCP サーバー: ...` と表示される。
- `.mcp.json` に新しいサーバーがあると、承認を求める確認画面がターミナルに出る。ウィンドウを隠して動かしていると Slack からは気付けず、セッションが止まったままになる。そのため `.mcp.json` はそのまま読ませない。`extra-mcp.json` に書いたサーバーには、この確認画面は出ない。
- 追加したサーバーのツールは**確認なしで実行される**。起動スクリプトが `mcp__<サーバー名>` を allow に足すため。
  MCP のツールは1回の操作ごとに確認が出るので、ブラウザ操作などが確認のたびに止まってしまう。それを避けるための扱い。
  使う人が承知して入れたサーバーとみなすので、ツールの中身（任意のスクリプトを実行できるものなど）を理解したうえで登録する。
  個別のツールだけ確認させたいときは、`channel-settings.json` の `ask` に書く（allow より優先される）。
- OAuth の認証が要るサーバー（HTTP 型など）は、先にターミナルの `/mcp` から認証しておく。Slack からは認証できない。
- claude.ai のコネクター（Gmail など）は、起動スクリプトが無効にしている（`ENABLE_CLAUDEAI_MCP_SERVERS=false`）。

## 許可リストへの追加（♾ 今後も許可）

実行許可のメッセージの **♾ 今後も許可** を押すと、今回の操作を許可したうえで、同じ種類の操作を許可リストに足すかをスレッドで確かめる。
**追加する** を押すと、状態ディレクトリの `allow-extra.json` に書き込む。**次に再起動したときから**、その操作は確認なしで実行される。
起動スクリプトが `channel-settings.json` の allow に足してから Claude Code に渡すので、動いているセッションには効かない。

- ルールは確認の中身から作る。自由な入力は受け付けない。
  - Bash / PowerShell: コマンドの先頭の語をプレフィックスにする。`git` / `npm` などはサブコマンドまで含める（例: `Bash(git status:*)`）。
  - Read / Grep / Glob: 対象のフォルダー以下の `Read` にする。例えば `C:\dev\foo\a.ts` を読んだなら `Read(//c/dev/foo/**)`。Grep / Glob は `path` のフォルダーを使う。
  - Edit / Write / MultiEdit / NotebookEdit: 対象のフォルダー以下の `Edit` にする（例: `Edit(//c/dev/foo/**)`）。
    Claude Code がパスで照合するルールは `Read(path)` と `Edit(path)` だけなので、この2つで作る。`Edit` は書き換え系のツール全部に、`Read` は Grep / Glob にも効く。
  - それ以外のツール: ツール名だけにする（例: `WebFetch`）。
- 次のものはルールを作らず、理由をスレッドに返す。
  - 複数のコマンドをつないだもの、リダイレクトを含むもの。
  - 次の操作に当たるコマンド。
    - 削除・移動・ネットワーク・プロセスの起動・権限やシステムの変更
    - 任意のコードの実行（`node` / `python` / `npx` / `uvx` など）
    - エージェントの CLI（`claude` / `codex` / `gemini` など）。別のエージェントに確認なしで操作させられるため。
    - `git push` / `reset` / `clean` などの破壊的な操作
    - スクリプトの実行（`npm test` / `npm run` / `dotnet run` など）。ファイルの編集が確認なしだと、スクリプトを書き換えてから実行できるため。
    - 読み取り系（`Get` / `Test` / `Select` など）以外の PowerShell コマンドレット
  - パスを取るツールで、範囲が広すぎるか、意図と違う範囲になりうるもの。具体的には次のどれかに当たるもの。
    - パスが読み取れない、相対パス
    - `..` や gitignore の特殊文字（`* ? [ ] ! # { }`）を含む
    - 浅すぎる（`C:\` や `C:\dev` 直下）
    - ホームフォルダーそのものか、その親
- **deny に当たるものは追加しない**。`channel-settings.json` と作業フォルダーの `.claude/settings.json` / `settings.local.json` の deny と照合し、当たったら「deny に当たるので追加しない」と、当たった deny をスレッドに返す。
  - Bash / PowerShell などは、範囲が重なる（どちらかがもう一方を含む）と当たると判定する。
  - フォルダー以下の `Read` / `Edit` は、そのフォルダーが deny の範囲に**丸ごと入る**ときだけ当たると判定する。具体的には、次のどれかの deny があるとき。
    - ツール全体の deny
    - 同じフォルダー以下全部の deny
    - 親のフォルダー以下全部の deny
  - `Read(.env)` や `Read(~/.ssh/*)` のように一部だけ重なる deny では断らない。Claude Code は allow より deny を優先するので、追加しても `.env` などは読めないまま。
  - deny の `./path` と `/path` は作業フォルダー基準、`~/path` はホームフォルダー基準とみなして照合する。
  - 確認したあと、追加する直前にも deny を読み直して照合する。
- `!rules` と送ると、追加したルールを一覧して、🗑 ボタンで消せる（次に再起動したときから反映）。
- 追加と削除はログ（`許可リストに追加` / `許可リストから削除`）に残る。

## このセッション中は全部許可（🔓）

`.env` に `SESSION_ALLOW_ALL=on` を書いたボットだけ、実行許可のメッセージに **🔓 このセッション中は全部許可** ボタンが出る。
押すと今回を許可したうえで、以後の実行許可にはブリッジが自動で allow を返す（ボタンは出さない）。

- 次のファイルの ask に当たる操作は自動許可から外し、今までどおりボタンで確かめる。
  - `channel-settings.json`（`-SettingsFile` で渡したもの）
  - 作業フォルダーの `.claude/settings.json` / `settings.local.json`
- deny に当たる操作は、Claude Code が確認を出す前に止める。だから全部許可の間も実行されない。
- ask との照合は次のとおり。
  - ツール全体のルールは、そのツールのすべてのリクエストに当たる。
  - シェルの中身付きのルールは、コマンドがそのプレフィックスで始まるときに当たる。
  - `Read` / `Edit` の中身付きのルールは、パスがそのフォルダー以下（`//`・`~/`・`./`・`/` 基準）のときに当たる。ファイル名だけのルール（`.env`・`*.pem`）なら、名前が一致するときに当たる。
  - 判断できないもの（コマンドやパスが読めない、途中にワイルドカードがあるパターン、ほかのツールの中身付きのルール）は、安全側に倒して当たると判定する。
- 自動で許可した操作は、最後に話しかけたスレッドに「🔓 自動許可: ツール名」と入力の先頭を残す。
- 解除されるのは次のとき。`/compact` では解除しない。
  - `!lock` を送ったとき
  - `!clear` などで新しい会話になったとき（hook の SessionStart で source=clear）
  - ブリッジが終了したとき（再起動・`!restart` を含む）
- `!status` に「全部許可: 有効（○時から）／無効」を出す。

> Slack のアカウントを乗っ取られると、有効な間は ask と deny 以外の操作が確認なしで実行される。個人のワークスペースで、手元のセッションに限って使う。

## ターミナル画面の確認と選択

Claude Code がターミナル側の選択画面（Slack に中継されない案内など）で止まったときに、Slack から画面を確かめて選択肢を選べる。

- `!screen` と送るか、無応答の警告の **🖥 画面を確認** を押すと、ブリッジがターミナルの画面を読む。`!screen` は Claude には渡さない。
  - 選択画面（`>` / `❯` の付いた選択肢）なら、選択肢をボタンで出す。押すと、その選択肢までカーソルを動かして Enter を送る。
  - 選択画面でなければ、画面の末尾をコードブロックで送る。トークンらしき文字列は伏せる。
- 送れるのは、**選択肢を選ぶキー操作（↑ / ↓ / Enter）だけ**。自由な文字は入力できない。
- ボタンを押すと画面を読み直し、見せたときと同じ選択画面のままのときだけキーを送る。画面が変わっていたら何も送らない。ボタンの有効期限は5分。
- 画面の読み取りとキーの送信は、`scripts\console.ps1` を子プロセスで実行して行う（ブリッジは Claude Code と同じコンソールを使っている）。
  Windows 以外の環境や、スクリプトが見つからないときは使えない。

## アプリのホームタブ

Slack でボットのアプリを開くと、ホームタブにブリッジの状態が出る。`app_home_opened` イベントと、App Home の Home Tab を有効にしておく。

- 許可ユーザーには、次を出す。それ以外のメンバーには、許可ユーザーだけが使える旨だけを出す。
  - 稼働中か停止中か、起動（停止）の時刻
  - 作業フォルダー
  - 話しかけられる場所（DM と許可チャンネルの件数）
  - 「今後も許可」で足したルールの件数
  - 使い方
- 起動したときに許可ユーザー全員のホームを「稼働中」にし、終了するときに「停止中」へ書き換える。
  プロセスが強制終了されると（終了処理が走らないと）「稼働中」のまま残るので、下の「最終更新」の時刻も見る。
- 状態ディレクトリに `home.json` を置くと、そのセッションのホームの文面を差し替えられる。ボットごとに口調や挨拶を変えたいときに使う。ホームを出すたびに読み直すので、再起動は要らない。
  - どの項目も省略できる。文字列の `{since}` は起動（停止）の時刻に、`{mention}` はボットへのメンションに置き換わる。
  - `body` を書くと、既定の情報と使い方の説明は出さない。
  - 読めないときや形が違うときは、ログに警告を残して既定の文面にする。
  ```json
  {
    "header": "📣 見出し",
    "running": "稼働中に添えるひと言（{since} から）",
    "stopped": "停止中に添えるひと言",
    "greetings": ["開くたびにこの中から1つ選んで出す", "もう1つ"],
    "body": ["本文の1行目", "本文の2行目"],
    "footer": "最終更新の前に出すひと言"
  }
  ```

## 状態の確認（`!status`）

「返事が来ない」ときに、まず見るもの。`!status` と送ると、スレッドに次を返す（Claude には渡さない）。

- 稼働開始の時刻と経過時間、作業フォルダー、Slack の接続状態
- Claude への返事を待ち始めた時刻
- 回答待ちの実行許可の件数
- 「全部許可」の状態（有効にしたボットだけ）
- 直近の hook 5件

## セッションの再起動・圧縮・クリア（`!restart` / `!compact` / `!clear`）

手元に行かずにセッションを立て直すための機能。channel のプロトコルには Claude Code にコマンドを送る手段が無い。
そこで、ターミナルの入力欄に**決まったコマンドだけ**を打ち込む（`!screen` と同じく `scripts\console.ps1` を使う。自由な文字は入力できない）。

- `!restart`: 状態ディレクトリに再起動フラグ（`restart.flag`）を置き、入力欄に `/exit` と Enter を送る。
  claude.exe が終わるとブリッジも終わり、`start.ps1` がフラグを見て再起動する。起動時の警告ダイアログには `dialog-answer.ps1` が答える。
  - 会話は引き継ぐ。フラグには、ブリッジが hook の記録から知った今の会話の `session_id` を書き、`start.ps1` は `--resume <session_id>` でその会話を開く。
  - id が分からないときや、その会話の記録（`~/.claude/projects/*/<session_id>.jsonl`）が無いときは、新しい会話で起動する。起動してから一度もやりとりしていない会話は、保存されない。
  - `--continue`（フォルダーで最新の会話を開く）は使わない。同じフォルダーで VS Code などの会話が後から作られていると、そちらを開いてしまうため。
  - `--resume` で起動して30秒以内に失敗で終わったときは、新しい会話で1回だけ起動し直す。Slack から戻せなくならないようにするため。
  - 次のメッセージは、Slack に「🟢 セッションを開始した」が出てから送る。20秒たっても claude.exe が終わらなければ、ブリッジがその旨を通知する。
- `!restart force`: `/exit` を送らずに claude.exe を強制終了する。ターミナルが応答中のときや、画面が読めないとき用。
  - `taskkill /T /F` で、claude.exe の子プロセス（ほかの MCP サーバー、Bash の子など）もまとめて止める。親が `claude.exe` / `node.exe` でなければ止めない。手で起動したシェルを巻き込まないため。
  - 会話の記録は逐次保存されているので引き継げる。ただし直前の応答は失われる。
  - 再起動した新しいブリッジは、古いブリッジのロックが残っていても、持ち主のプロセスが死んでいれば取る。生きていても最大10秒は取り直しを試し、それでも取れなければ縮退モード（Slack に接続しないモード。[用語](reference.md#用語)）に入る。
- `!compact`: 入力欄に `/compact` と Enter を送る。終わると hook が「🧹 会話を圧縮した」を通知する。
- `!clear`: 入力欄に `/clear` と Enter を送る。会話は捨てられ、新しい会話になる。元には戻せないので、残したい文脈があるなら `!compact` を使う。
  終わると hook が「🧹 会話をクリアした」を通知する。
- `/exit`・`/compact`・`/clear` は、画面が**空の入力欄で待っているときだけ**送る。応答中・選択画面・打ちかけの文字があるときは送らず、その旨を返す。
  Claude Code は応答中も入力欄を描くので、応答中の表示（`esc to interrupt`）があるときも送らない。
- 再起動のあとの `--resume` と development channels の組み合わせや、ダイアログへの自動応答は、Claude Code の版によって変わりうる。
  - 自動応答は、画面にタイトルの `development channel` と選択肢の `local development` の両方が出たときだけ答える。2.1.285 での文言は「WARNING: Loading development channels」と「I am using this for local development」。
  - 再起動の前に画面を消すので、前のセッションの発言に反応することはない。
  - 動かなくなったら、`start.ps1` の `$DevChannelDialogPattern` / `$DevChannelChoicePattern` を直す。

## Claude Code 側の出来事の通知（hook）

Slack からは見えない Claude Code 側の出来事を、Claude Code の hook を通して Slack に通知する。主な狙いは、使用量の上限とターミナル側の入力待ちに気付くこと。

- 起動スクリプトは、`--settings` に渡す設定へ hook を注入する。hook は `dist\src\hook.js` を実行し、状態ディレクトリの `hooks.jsonl` に1行追記するだけ。
  ブリッジは1.5秒ごとに増えた分を読んで、Slack に出す。MCP の stdout は MCP 専用なので、hook はブリッジと直接はやりとりしない。
- `start.ps1` は起動ごとに一意の値を環境変数 `SLACK_CHANNEL_SESSION_TAG` に入れ、hook はその値を行の `session_tag` に記録する。
  ブリッジは自分と同じ値の行だけを扱う。同じ状態ディレクトリを使う別のセッションの終了や入力待ちを、混ぜないため。`start.ps1` を使わずに起動したブリッジは、すべての行を扱う。
- 通知の宛先は、最後に話しかけられたスレッド。まだ話しかけられていなければ、許可ユーザー全員の DM。
- 通知するものは次のとおり。
  - ターミナル側の入力待ち（Slack に中継されない許可の確認、elicitation、サブエージェントの質問）。**🖥 画面を確認** ボタンを付ける。Slack に中継中の許可があるときは、重ねて出さない。
  - Claude が Slack に返事をしないまま応答を終えた（`Stop`）とき、または入力待ちのまま止まっている（`idle_prompt`）とき。Slack への返事を待っているときだけ出す。
  - 応答の失敗（`StopFailure`）。使用量の上限（rate limit）・混雑・認証・請求などの種別と、あれば詳細を添える。
  - 使用量の上限からの自動再開の案内（`quota_auto_resume_*`）。
  - セッションの開始（作業フォルダー付き）・終了・会話のクリア・圧縮。`/clear` のときは終了を出さず、「会話をクリアした」だけを出す。
- 上限で止まったあとに自動で再開する設定 `autoContinueAtUsageLimit` は、Claude Code の managed settings かデスクトップアプリでしか設定できない。CLI の設定や `--settings` に書いても効かない。
  上限に達したらこの hook で通知するので、再開の操作は手元で行う。
- `node` が PATH に無いと、hook は注入されない（起動スクリプトが警告を出す）。hook のイベント名や欄は Claude Code の版で変わりうる。通知が出ないときは、`hooks.jsonl` に何が記録されているかを見る。

## セッションを並べる

プロジェクトごとに作業フォルダーや権限を分けたいときは、セッションをもう1つ並べられる。その場合は、**Slack アプリも別に作る**。
同じアプリで Socket Mode の接続を2本張ると、Slack はイベントを2本に振り分ける（両方には配らない）。そのため、メッセージがもう片方に取られて消える。

1. 2つ目の Slack アプリを、[slack-app-manifest.yaml](../slack-app-manifest.yaml) から作る。名前とボットの表示名は変えておく。
2. 別の状態ディレクトリ（例: `%USERPROFILE%\.claude\channels\app2`）に、そのアプリの `.env` と `access.json` を置く。
   `access.json` の `channels` には、そのセッションで使うチャンネルだけを書く。既定の場所の外に置くなら、deny も足す（[権限の設計](security.md#権限の設計)）。
3. `-StateDir` と、必要なら `-SettingsFile`（相対パスはリポジトリ基準）を付けて起動する。
   ```powershell
   scripts\start.cmd C:\path\to\app2 -StateDir "$env:USERPROFILE\.claude\channels\app2" -SettingsFile C:\path\to\app2-settings.json
   ```

- 状態ディレクトリの中身（`.env`・`access.json`・ロック・`allow-extra.json`・ログ）は、セッションごとに分かれる。ブリッジには、`mcp.json` の環境変数で状態ディレクトリを渡す。
- 一時ファイルは `%TEMP%\claude-slack-channel\<状態ディレクトリ名>\` に分かれる。`claude.exe` のコマンドラインにこのパスが入るので、どのセッションかを見分けるのにも使える。
- 設定ファイルを作業フォルダーの中に置くなら、その場所の `Edit(...)` を deny に入れておく。Claude が自分で設定を書き換えて権限を広げられないようにするため。
